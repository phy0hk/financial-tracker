## CORS Fix — API calls (Section 4)

The web client issues cross-origin API calls with `credentials: 'include'` (auth
cookies + the `Authorization` bearer header). Because `CORS_ORIGIN` was `*`, the
server responded with `Access-Control-Allow-Origin: *`, which the CORS spec
forbids on credentialed responses — so login/register, logout, the hybrid sync
push, and every admin call were blocked by the browser.

- `apps/server/src/index.ts`: the Hono `cors` middleware now resolves
  `Access-Control-Allow-Origin` dynamically. A `resolveCorsOrigin()` helper
  echoes the request's own `Origin` when `CORS_ORIGIN` is `*` (dev-friendly) and
  matches against a comma-separated allowlist when `CORS_ORIGIN` lists one or
  more explicit origins (production). `credentials: true`,
  `allowHeaders: ['Content-Type', 'Authorization']`, and the
  `GET/POST/PATCH/DELETE/OPTIONS` allowlist are unchanged; the middleware now
  also emits `Vary: Origin` so cached responses are keyed per origin. The
  middleware is registered directly with Hono so its `204 No Content` preflight
  response is preserved instead of falling through to a `404`.
- `apps/server/wrangler.jsonc` keeps `CORS_ORIGIN: "*"` for local development;
  set it to the deployed web origin (e.g. `https://app.zerotracker.dev`) in the
  `production` env before deploying so credentialed requests are restricted to
  the real frontend.

## Running the Workspace

```bash
bun install
bun dev
```

Run typechecking with:

```bash
bun run typecheck
```

The CORS change in `apps/server/src/index.ts` introduces no diagnostics in the
edited file. The current `bun run typecheck` reports one pre-existing import error in
`apps/web/src/context/StorageContext.tsx` (`createIndexedDbConnection` is not
exported by `@zerotracker/core/db`, which only ships `createExpoSQLiteConnection`
and `createSqliteWasmConnection`); the earlier `BufferSource` diagnostic in
`packages/core/src/crypto/index.ts` no longer surfaces. Production deployment
still requires `JWT_SECRET`, database/Hyperdrive configuration, a real
`VITE_API_URL`, and `CORS_ORIGIN` set to the deployed web origin (see the CORS
section above). Tesseract.js must be bundled or loaded locally by the web host
before invoking `OCRScannerModule.scan()`.
